# 输入框改版与多模态后续分工

日期：2026-06-09

## 2026-06-09 提交前状态更新

本页最初用于记录输入框改版后的后续分工，下面“当前边界”和“需要当前模型继续做的部分”保留为当时的任务拆分背景。后续提交准备中，多模态主链路已推进到可演示 MVP：

- Android 相机/相册图片可上传到后端。
- 后端已提供 `POST /api/multimodal/images` 和 preview 接口，返回 `image_id`、`summary`、`query_text` 和 `image_plan`。
- `ChatRequest.images` 已接入，后端会把 `image_plan` 转成文本检索线索并复用现有 RAG。
- 图片-only 发送流程已接入 Android 输入栏。
- 当前仍不是图像向量搜同款，也不承诺真实价格/库存/优惠识别。

最终提交口径：图片输入写成“text-first 多模态 MVP 已接入，需最终 provider/实机验证”，不要再沿用早期未接后端的表述。

## 本轮已完成

- Android 输入框改成一个大圆角容器：上半区只承载文本输入，下半区固定放工具按钮。
- 左下角 `+` 已进入输入框内部，并弹出向上的附件菜单。
- 附件菜单已提供两个入口：`拍照`、`从相册选择`。
- 语音输入入口已移到输入框底栏。
- 录音态已改成底部横向模式：左侧 `+`、中间虚线 / 波形 / 计时、右侧停止与圆形发送按钮。
- 发送按钮已改为圆形，并使用向上箭头样式。

## 历史边界（已被上方状态更新覆盖）

- 当时状态：拍照和相册选择只完成 Android 端入口与状态提示。
- 当时状态：选中图片仍停留在 Android 本地状态，尚未参与后端请求或 RAG retrieval query。
- 当时判断：Spark 5.3 如果不能处理图片 / 视频输入，就不适合作为图片理解主模型。
- 用户原图不应写入 Git，也不应进入现有 eval 数据，除非后续单独做脱敏样例。

## 需要当前模型继续做的部分

这些任务涉及图片 / 视频理解、模型能力判断或跨端链路，不适合直接交给不支持多模态的 5.3：

1. 设计图片上传 API：Android 传图片到后端，后端返回结构化 `image_plan`。
2. 接入可用的多模态模型：抽取品类、品牌、包装文字、视觉属性和置信度。
3. 把 `image_plan` 拼进现有 retrieval query，并记录 trace。
4. 低置信度图片识别的追问策略。
5. 如果做视频输入，先限定为关键帧抽取，不直接做长视频理解。

## 可以交给 5.3 AI 朋友的部分

这些任务不要求模型直接看图，可以交给 5.3 节省额度：

1. 调整附件菜单文案和空状态提示。
2. 整理图片输入验收 checklist。
3. 补 `docs/26_advanced_route_research.md` 中多模态阶段的实现清单。
4. 根据已有 `image_plan` JSON 样例补 API contract 文档。
5. 为纯文本 fallback 写测试 query，例如“我刚才传的图是防晒，预算 200 以内”。

## 下一步建议

先做轻量 Stage 1：

```text
Android 图片入口
  -> 后端接收图片
  -> 多模态模型抽取 image_plan
  -> image_plan + 用户补充文字
  -> 复用现有 RAG retrieval
  -> 商品卡片与 trace
```

暂时不做 Google Lens 式全网识图、视频长序列理解、真实图搜图向量索引。
