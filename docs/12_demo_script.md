# Demo 脚本

日期：2026-05-28

用途：录制第一版 1 分钟闭环 Demo，证明当前版本已经能跑通 Android 原生端、FastAPI、RAG 检索、Doubao 生成、商品卡片和详情弹窗。

## 录屏前检查

1. 后端运行在 `0.0.0.0:8000`，Android 模拟器通过 `http://10.0.2.2:8000` 访问。
2. 本地 `.env` 已配置真实 `ARK_API_KEY`、`ARK_MODEL`，且 `MOCK_LLM=false`。
3. 如果真实 API 需要代理，终端使用：

```bash
export https_proxy=http://127.0.0.1:7897
export http_proxy=http://127.0.0.1:7897
```

4. Android App 使用最新 Debug 版，首页能看到 3 个快捷问题：
   - `油皮通勤防晒`
   - `敏感肌修护`
   - `信息不足追问`

## 1 分钟展示顺序

### 0-10 秒：打开 App

展示标题 `RAG 美妆导购` 和 3 个快捷问题。说明一句：

> 这是一个原生 Android + FastAPI 的美妆导购 Agent，商品卡片和详情字段来自本地数据源。

### 10-30 秒：油皮通勤防晒

点击 `油皮通勤防晒`。

期望展示：

- 用户消息：`我是油皮，想要200元以内通勤防晒`
- 流式回复逐步出现。
- 商品卡片展示品牌、标题、价格、图片和标签。
- loading 结束后按钮回到 `发`。

讲解重点：

> 预算、肤质和场景会先进入检索约束，商品卡片里的价格和图片不由模型生成。

### 30-45 秒：商品详情

点击推荐商品卡片。

期望展示：

- 商品图片。
- 价格、类目。
- 推荐理由。
- 适合人群、使用场景、卖点、注意事项。

讲解重点：

> 详情页用于证明推荐不是纯聊天文本，而是可以落到结构化商品证据上。

### 45-60 秒：信息不足主动追问

关闭详情弹窗，重启 App 或开启新会话，点击 `信息不足追问`。

期望展示：

- 用户消息：`我想买护肤品，你推荐什么？`
- 助手不直接推荐商品。
- 助手追问：`你更在意肤质、预算，还是防晒/修护/控油这类具体功效？`

讲解重点：

> 信息不足时系统会先追问，而不是为了凑推荐而乱推商品。

## 可选补充：敏感肌修护

如果录屏时间允许，点击 `敏感肌修护`。

期望展示：

- 召回理肤泉、薇诺娜等修护面霜。
- 对“酒精/刺激”这类排除条件保持谨慎表述。
- 如果模型输出越界，后端 guardrail 会触发二次改写或安全兜底。

讲解重点：

> 对于资料没有明确支持的“不含/不会刺激”断言，后端不会让模型直接放大成确定承诺。

## 当前边界

1. 当前 Demo 主线是美妆文字导购，不展示图片输入、语音或购物车。
2. 当前 enriched 数据已覆盖完整 25 条美妆商品，但 Demo 主线仍聚焦文字导购。
3. Guardrail 是规则版，不是完整 groundedness judge；后续需要继续沉淀 failure cases。
