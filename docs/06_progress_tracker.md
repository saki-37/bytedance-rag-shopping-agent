## 当前一句话状态

已经跑通了第一条端到端链路：

> Android 文字输入 -> FastAPI `/api/chat/stream` -> 美妆商品检索 -> mock 流式回复 -> Android 展示回复与商品卡片。

但当前还只是 **MVP 闭环**，不是最终参赛版本。最主要的缺口是：真实 Doubao 调用后的推荐编排还比较粗、Chroma 向量库还没有进入稳定主链路、评测闭环还没有成型。

## 接下来优先级

### P0：把当前闭环变成可演示版本

1. 重新 Run Android，确认 loading 状态能从 `中` 回到 `发`。
2. 连续跑 3 个 golden queries：
   - 油皮 200 元内通勤防晒。
   - 敏感肌屏障修护面霜。
   - 信息不足时主动追问肤质/预算。
3. 商品卡片支持点击，打开模拟详情页或底部弹窗。
4. 详情页展示数据源字段：
   - 商品名、品牌、价格、类目。
   - 适合人群、使用场景、卖点、注意事项。
   - 推荐理由和数据依据。
5. 为 demo 加基本错误状态：
   - 后端断开时显示可理解错误。
   - 空输入不能发送。

### P1：从 demo mock 走向真实 RAG

1. 配置本地 `.env`，接入真实 Doubao / ARK OpenAI-compatible API。
2. 构建 Chroma 索引，并确认后端运行时真实使用向量召回。
3. 扩展美妆增强数据：
   - 当前 6 条 -> 至少覆盖 25 条美妆。
   - 补全肤质、功效、成分/禁忌、使用场景、适合/不适合人群。
4. 强化检索逻辑：
   - 预算硬过滤。
   - 肤质/功效/场景加权。
   - 否定约束，如不要酒精、不要刺激、不要太油。
5. 增加多轮上下文：
   - 用户先说模糊需求。
   - Agent 主动追问。
   - 用户补充后再推荐。

### P2：主打能力和答辩亮点

1. 商品对比：
   - 2-3 个商品从价格、肤质、功效、注意事项对比。
2. 反馈闭环：
   - 用户标记推荐是否有用。
   - 记录失败 query。
   - 形成 prompt / 数据增强迭代记录。
3. 评测脚本：
   - 检索命中。
   - 是否错误推荐超预算商品。
   - 是否编造价格/库存/优惠。
   - 是否在信息不足时追问。
4. UI 打磨：
   - 商品图片真实加载。
   - 卡片排版、详情弹窗、加载状态、错误重试。
5. 可选多模态：
   - 图片输入 / 拍照找货作为 stretch goal，不抢主线。

## 当前最应该做的下一步

先做 **3 条 Android 端 golden query 复验**。

原因：

- 卡片可点击已经完成第一版，接下来要确认它在模拟器内可稳定演示。
- 3 条 query 复验能证明当前闭环不是单点偶然成功。
- 完成之后，当前版本就能录一个第一阶段演示视频。

完成标准：

- 点击商品卡片能看到详情。
- 详情字段全部来自 `raw` 或 `enriched` 数据，不由模型编造。
- Android 端连续跑 3 条 query 后，loading 能正常结束，卡片和回复能正常展示。
