# 数据集盘点

日期：2026-05-21  
数据目录：`字节项目/ecommerce_agent_dataset/`

## 结论先行

这份数据集适合做端到端 MVP：结构规整、规模可控、每条商品都有图片和 RAG 文本素材。

但它还不适合直接作为「复杂约束导购」的最终数据层。当前很多关键信息仍藏在自然语言描述里，例如肤质、材质、使用场景、禁忌条件、性能卖点、适合人群等。后续需要补一层结构化字段，才能稳定支持筛选、反选、对比和反幻觉。

建议策略：

- 保留官方原始数据，不直接覆盖。
- 新增标准化/增强后的派生数据层。
- 把补充字段设计成可解释、可评测、可用于商品卡片展示的结构。

## 当前统一字段

所有商品都有以下顶层字段：

- `product_id`
- `title`
- `brand`
- `category`
- `sub_category`
- `base_price`
- `image_path`
- `skus`
- `rag_knowledge`

`rag_knowledge` 中所有商品都有：

- `marketing_description`
- `official_faq`
- `user_reviews`

FAQ 数量大致为 1-6 条，用户评价大致为 3-6 条。文本素材足够支撑基本 RAG 检索。

## 类目观察

### 美妆护肤

规模：25 条。

子类目分布：

- 精华：7
- 防晒：3
- 面霜：3
- 化妆水：2
- 蜜粉：2
- 眼霜：2
- 洁面、唇釉、卸妆、粉底液、面膜、眉笔：各 1

价格范围：52 - 1690，价格跨度大，适合做预算约束。

优势：

- 描述里有丰富的肤质、功效、成分、注意事项和使用场景。
- 很适合展示「敏感肌」「油皮」「抗初老」「控油」「防晒」「修护屏障」等导购语义。
- 用户评价里有正负反馈，适合做风险提示和反幻觉约束。

短板：

- 结构化字段不足。肤质、功效、成分、禁忌、适用场景大多还在自然语言里。
- 防晒只有 3 条，如果只做防晒垂直场景，商品池偏小。
- 美妆类只有 25 条，如果官方严格期待 50-100 条同类数据，需要扩充或跨子类组织场景。

初步判断：

美妆护肤仍然是最适合主线 Demo 的类目，但建议把定位从「只做防晒」调整为「护肤/防晒/底妆的肤质友好导购」。这样可以利用更多现有商品，同时保留敏感肌、油皮、预算、场景、成分禁忌等复杂约束。

### 数码电子

规模：25 条。

子类目：

- 智能手机：10
- 平板电脑：7
- 笔记本电脑：6
- 真无线耳机：2

优势：

- SKU 参数丰富，例如存储、颜色、版本、芯片、屏幕尺寸、内存、固态硬盘等。
- 很适合做明确参数筛选和价格比较。

短板：

- 商品描述里存在明显未来型号，例如 iPhone 17 Pro、M5 等，作为模拟数据可以用，但如果答辩被追问真实性，需要解释是脱敏/模拟数据。
- 对你的主线兴趣和作品叙事连接弱于美妆护肤。

适合作为：

- 对比决策备选场景。
- 预算/性能/用途筛选的测试集。
- 非主线类目，用来证明系统可扩展。

### 服饰运动

规模：25 条。

优势：

- 包含 T 恤、跑鞋、篮球鞋、徒步鞋、瑜伽裤、背包、帽子等。
- 很适合补充材质、尺码、颜色、运动场景、天气/户外条件。
- 和主办方提到的「纯棉」这类材质型需求高度相关。

短板：

- 当前材质、版型、适用运动强度等字段多在描述里，没有独立结构。
- SKU 组合较多，后续商品卡片和详情页要小心不要被 SKU 复杂度拖住。

适合作为：

- 多类目扩展测试。
- 「材质/尺码/运动场景」类复杂约束示例。

当前状态：

- 已完成 5 条 V2-B enriched 样例：`p_clothes_001`、`p_clothes_002`、`p_clothes_007`、`p_clothes_014`、`p_clothes_018`。
- 样例覆盖短袖 T 恤、速干训练短袖、跑步鞋、徒步鞋、通勤户外背包。
- 每条样例都按 V2 schema 标注了 `variants`、`attributes.specifications`、`source.attribute_provenance` 和 `category_attributes.apparel`。
- 服饰 query benchmark 见 `data/eval/apparel_queries.json`。

### 食品饮料

规模：25 条。

优势：

- 适合做口味、包装、数量、健康偏好、价格约束。
- 价格区间低，场景容易理解。

短板：

- 复杂导购深度相对弱。
- 食品安全、健康功效等回答需要更谨慎，避免夸大或伪健康建议。

适合作为：

- 简单筛选和商品卡片展示。
- 不建议作为主线。

## 建议主线场景

当前最稳主线：

> 肤质友好的护肤/防晒/底妆导购 Agent。

不要把范围压得太窄到「防晒专门导购」，因为现有防晒商品只有 3 条。更好的范围是：

- 用户输入肤质：油皮、干皮、混油、敏感肌。
- 用户输入需求：防晒、修护、控油、抗初老、提亮、保湿、底妆持妆。
- 用户输入限制：预算、不要酒精/香精/刺激成分、不要太油、不要高价、不要某品牌。
- Agent 能主动追问：肤质、预算、使用场景、是否敏感、是否需要上妆/户外。
- Agent 能对比：2-3 个候选商品，从价格、适合肤质、功效、注意事项、用户评价风险做结构化比较。

如果需要满足 50-100 条数据口径，可以有两种策略：

1. 主线使用 25 条美妆护肤数据，答辩说明官方要求是 50-100 条脱敏电商数据总量，本系统总库为 100 条，Demo 聚焦其中一个垂直类目。
2. 扩充美妆护肤到 50 条左右，新增同结构商品，并补全结构化标签。

建议先走第 1 种，等 MVP 跑通后再决定是否扩充美妆数据。

## RAG 使用建议

每个商品可以拆成 3 类 chunk：

1. 商品主信息 chunk：标题、品牌、类目、价格、规格、核心卖点。
2. 官方知识 chunk：营销描述和 FAQ，适合回答功效、使用方式、对比理由。
3. 用户反馈 chunk：评价里的优缺点、踩雷点、适合/不适合人群，适合生成风险提示。

推荐链路：

- 先用结构化字段做硬过滤：价格、类目、肤质、排除条件。
- 再用向量检索召回相关商品。
- 最后让模型基于召回商品生成解释，且要求引用商品字段，不允许编造未提供信息。
