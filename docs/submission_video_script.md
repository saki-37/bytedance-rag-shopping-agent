# 最终提交演示视频脚本

日期：2026-06-10

目标：按 **10 分钟以内完整录制版**组织素材。若最终平台或评审偏好短视频，再从同一批素材剪成 3-5 分钟主版；不要重新设计一条完全不同的故事线。

拍摄方式定调：

- 用真机。开场保留 3-5 秒手持实拍点开 App 图标，然后切手机录屏，证明是原生 Android App。
- 先录素材后配音。每个 query 录 2-3 遍，取响应最快、画面最稳的一条；等待模型的空白段后期剪掉。
- 全程只用回归或实测过的固定 query。语音输入只展示一次，放在最稳的 query 上；其他语音素材可以作为备用。
- 本次录屏可临时切到 Yunwu + `gpt-5.5` 提速，但必须在画面里用 `/health` 确认 `mock_llm=false`、`llm_provider=yunwu`、`llm_model=gpt-5.5`。正式 benchmark 仍按 Ark / Doubao 口径讲。

| 回归抽样 | 至少跑过防晒推荐、安热沙/安耐晒 alias、多轮对比、图片输入、ASR、TTS 开关。 |
| 真机连接 | USB 连接后重跑 `adb reverse tcp:8000 tcp:8000`；若用真机局域网地址，确认 `backend.lan.url` 是当前电脑 IP。 |
| ASR sidecar | 如果展示语音输入，先启动 `~/asr-lab（本地 ASR 工具目录，按自己环境替换）/asr_service.py --port 8765`，并用短音频确认 `/api/asr/transcribe` 可用。 |
| TTS | 打开系统媒体音量，确认中文 TTS 可播报；录屏前试一次能否录到声音，录不到也要保留可见的“播放中/停止”状态。 |
| 多模态图片 | 手机相册里提前放好安热沙/安耐晒防晒图片，优先用 `p_beauty_010` 对应商品图或已验证截图。 |
| 隐私 | 设置、购买对象、终端画面不要露真实手机号、地址、API Key、代理配置和私人路径。 |

## Amy 三件套固定台本

这段来自 2026-06-10 Android 展示 trace 的复盘，适合替换或补强上面 `5:05-5:55` 的多轮对比段。优先用于复录，因为它同时展示 `scene_bundle`、商品卡片、序号指代、卡片裁剪和尺码 follow-up，比临场自由发挥稳。

录制前先新建会话，避免继承旧商品卡片。用户输入可以手打，也可以语音输入后确认发送。下面三轮尽量逐字使用。

### 第 1 轮：Amy 户外运动三件套

用户输入：

> 我想给我的朋友 Amy 买一套生日礼物的衣服。她以户外运动为主，身高170，是女生。想给她搭配一套运动系三件套，来个帽子，然后来个上衣，再来个裤子，可以帮我各搭配一件吗？

预期画面：

- 商品卡片按三件套槽位出现：帽子、上衣、裤子各一件。
- 当前回归预期是 `p_clothes_019` 帽子、`p_clothes_021` 速干T恤、`p_clothes_017` 户外裤。
- 如果真实模型回答文案略有差异，画面重点看卡片槽位是否完整，不要口播具体商品 ID。

可直接读的口播：

> 这里我不是让模型随便推荐三件商品，而是让 Planner 把需求拆成三个检索槽：帽子、上衣、裤子。检索层会按槽位各取一张商品卡片，所以不会因为某个裤子分数更高，就把帽子挤掉。

### 第 2 轮：第二款和第三款对比

用户输入：

> 嗯，第二款和第三款可以给我出一个比较吗？

预期画面：

- 只展示第 2 款和第 3 款对应的两张卡片。
- 不应再把第 1 款帽子或其他旧商品混进对比卡片。
- 表格或回答围绕上衣与裤子比较，商品顺序和上一轮卡片一致。

可直接读的口播：

> 这一轮展示的是多轮商品指代。客户端会把上一轮卡片的 product_ids 带回后端，后端把“第二款和第三款”解析成指定两件商品，并且最终只把这两张卡片交给回答层。

### 第 3 轮：上衣尺码追问

用户输入：

> 呃，上衣的话，你有什么推荐的尺码吗？如果是根据我朋友的这个身材的话。

预期画面：

- 只返回上一轮三件套里的上衣卡片。
- 不应返回裤子，也不应把“这个身材”误解成“这个商品”。
- 回答应基于商品资料和已知身高信息保守建议，并提醒还需要体重、胸围或平时尺码。

可直接读的口播：

> 这里的重点是 follow-up 不丢上下文。用户没有再说商品名，只说“上衣”，系统会从最近商品池里找回上衣卡片，再基于已有的 170cm、女生、户外运动场景给出保守尺码建议。

剪辑建议：

- 完整版保留三轮，约 70-100 秒。
- 短版只保留第 1 轮卡片完整出现和第 2 轮只剩两张对比卡片；第 3 轮可用字幕或 5 秒快剪带过。
- 这段可以替代普通的“第一款和第三款怎么选”，因为它更贴近真实购物任务，也更能说明工程修复后的稳定性。

## 备用方案

1. `gpt-5.5` 如果慢或 Planner JSON 不稳，切回 `gpt-5.4-mini` 或 `gemini-3.5-flash`，但视频口播必须和 `/health` 一致。
2. 多模态图片如果真实 provider 不稳，只展示已验证成功的一次，不现场换图；不要说成图像向量搜同款。
3. ASR 如果现场噪声影响大，只展示转写成功的备用素材；主链路用手打 query。
4. TTS 如果录屏录不到声音，保留可见的播放状态、停止按钮和设置页，配音说明系统 TTS 已接入且依赖设备中文语音引擎。
5. 购买对象里不要填真实隐私信息；如果需要展示地址电话字段，用脱敏假数据或只展示对象名。

## 最终检查

- 完整版不超过 10:00；短版不超过目标平台要求。
- 前 60 秒内必须出现真机、真实模型口径、流式回答、商品卡片。
- 多模态、语音输入、TTS/无障碍、购买对象、新建对话都至少有一个可剪镜头。
- 视频中没有真实 Key、手机号、地址、代理配置、私人图片、未脱敏 `.env`。
- 口径保持保守：text-first 图片理解、本地 ASR sidecar、Android 系统 TTS、演示级购买对象记忆、非真实交易系统。
